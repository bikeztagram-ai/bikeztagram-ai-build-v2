# Autobot Quality Standard

This document records the standing rule for every future Bikeztagram AI product batch: the autonomous builder must receive a precise implementation specification defining the user outcome, runtime behaviour, architecture/integration direction, feature-specific professional quality bar, constraints, representative acceptance scenarios, regression protection and completion evidence. Passing tests or compiling is not sufficient when the intended capability is behavioural or creative. The builder must implement the full intended outcome rather than the narrowest technically valid subset, and verification must demonstrate meaningful behaviour with representative contrasting inputs where applicable. Batch objectives should be written against the end-game specification and should incorporate lessons from prior batch reviews.
