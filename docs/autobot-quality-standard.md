# Autobot Quality Standard

This is the standing rule for every future Bikeztagram AI product batch: the autonomous builder must receive a precise implementation specification defining the concrete user outcome, runtime behaviour, architecture/integration direction, feature-specific professional quality bar, constraints/non-goals, representative acceptance scenarios, regression protection and completion evidence.

The builder must implement the full intended outcome rather than the narrowest technically valid subset. Where creative or behavioural intelligence is required, verification must demonstrate meaningful behaviour with representative contrasting inputs/briefs, not merely schema existence or fixed happy-path assertions. Passing tests or compiling is not sufficient evidence of completion when production behaviour is the requirement.

Every batch must be written against the end-game specification and must incorporate lessons from prior batch reviews. Inspect existing contracts first, preserve working systems, use check-fix-check-continue, and report genuine external-provider limitations truthfully.
