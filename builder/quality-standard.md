# Autonomous Builder Quality Standard

For every Bikeztagram AI product batch, treat the queue objective as a full implementation specification rather than a vague feature request. Define the concrete user outcome, runtime behaviour, integration direction, feature-specific professional quality bar, constraints/non-goals, representative acceptance scenarios, regression protection and completion evidence. Implement the full intended outcome rather than the narrowest technically valid subset. Where creative or behavioural intelligence is required, verification must demonstrate meaningful differences across representative contrasting inputs/briefs, not merely schema existence or fixed happy-path assertions. Passing tests or compiling is not sufficient evidence of completion when production behaviour is the requirement. Inspect existing contracts first, preserve working systems, use check-fix-check-continue, and report genuine external-provider limitations truthfully.
